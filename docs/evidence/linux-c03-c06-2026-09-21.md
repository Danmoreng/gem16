- `2026-09-21-linux-c03-natural-12b-d2`

The first four 12B fixed-D2 attempts are retained. They reproducibly failed with

without destroying or reallocating its captured fixed-D2 graphs.

## C05/C06 SDK and Pi behavior

Pinned clients were Python SDK 2.50.0, openai-node 7.10.0 and unmodified Pi
0.85.0. The following passed on both public fixed-D2 profiles:

- Python SDK replay/tool/Unicode/output-limit cases;
- TypeScript SDK replay/tool/Unicode/output-limit cases;
- practical Pi read/edit/bash-test task with cache reuse and no slot rebuild;
- manual and automatic compaction, fork, branch change, parent resume and new
  session behavior;
- all explicit unsupported/error boundaries; and
- cold resume from retained history in a new Pi and server process.

The successful final/affected evidence is in:

- `2026-09-21-linux-c05-c06-v2` (12B TypeScript, Pi, lifecycle and boundaries),
- `2026-09-21-linux-c05-c06-12b-python-v4`,
- `2026-09-21-linux-c05-c06-26b-v3`,
- `2026-09-21-linux-c05-cold-resume-12b-v2`, and
- `2026-09-21-linux-c05-cold-resume-26b`.

Failed attempts remain retained. The first Python attempt used locally installed
SDK 2.54.0 instead of the repository pin. The first 26B matrix found the reset
loss described above. The first Linux cold-resume attempt copied its fixture to
Pi's migration root, where Pi moved it before `--session` opened it; the harness
now keeps the immutable copy in a subdirectory.

Reasoning replay, per-request sampler controls, required/named tool choice and
`parallel_tool_calls=false` remain visibly unsupported exactly as documented.
The passing boundary tests prove early rejection, not support for those features.

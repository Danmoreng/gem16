## M05 scope

M05 owns a deterministic, bounded compiler slice for attention projection weights only. The promoted conversion
is performed by a versioned native C++20 batch backend; the Python implementation is retained as an independent
oracle/fixture/report aid and is never a production fallback:

- BF16 source matrices Q/K/V/O to E4M3FN FP8 payloads;
- one BF16 scale per output row;
- bounded row-tile source access rather than whole-model or all-attention materialization;
- deterministic encoder fixtures, reports, and ordinary-BF16-versus-Unsloth comparisons.

M05 does not own NVFP4 (M06), head format selection (M07), the first complete artifact or direct loader (M08),
activation quantization, accumulation or runtime activation changes, 26B execution, or any 12B behavior change.
The C++ loader wording for M05 is limited to schema, binding and operator validation. M08 owns the first complete
direct-load artifact and loader integration.

## Canonical representation and arithmetic

For each logical matrix `W: [N,K]`, the canonical output is:

```text
weight:       F8_E4M3 [N,K]
weight_scale: BF16    [N,1]
```

M05 v1 uses deterministic rowwise max-absolute scaling. The normative encoder must use round-to-nearest, ties to
even; finite E4M3FN saturation; explicit little-endian payloads; and explicit BF16 scale rounding. NaN and Inf
source values are rejected. An all-zero row uses scale `1.0`. No synthetic global V is allowed: where the source
contract omits a global V projection, the compiler records that omission and does not invent a V tensor.

The representation is weight-only. Runtime dynamic activation scaling, accumulation ordering and BF16 output
boundaries are not changed by M05.

## Drift from the accepted M04 interface

The old M05 suggested commands use `--stage` and do not match the accepted M04 action-first CLI or its required
plan/manifest inputs. M05 must preserve the accepted `plan`, `compile`, `verify` and
`compare-reproducibility` actions and add an explicit profile/plan path instead of reviving the stale `--stage`
interface.

M04 requires complete source coverage through an output operation or an exact exclusion. An attention-only M05
partial artifact must therefore make the disposition of every non-attention source tensor explicit in its
profile/plan before encoder implementation: no family may be silently dropped, and no implicit passthrough may be
assumed. The plan must retain auditable exclusion or declared partial-artifact records while keeping the result
clearly non-complete and non-runtime-loadable until M08.

## Non-goals and stop conditions

Diagnostic native full artifacts now exist, but no clean release artifact or M05 acceptance exists. Stop before any
clean release run if the native profile/plan cannot represent complete non-attention coverage, if source locks or the
M04 contract drift, or if implementation would require changing runtime activation or accumulation semantics. Native
support must fail visibly; Python fallback is forbidden. M06+ remain blocked behind their dependency gates.

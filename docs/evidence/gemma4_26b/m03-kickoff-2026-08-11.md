## Authorization and scope

The project owner authorized M03 on the long-lived 26B feature branch. M03 is limited to exact source and
compiled-hybrid tensor contracts, role/residency classification, canonical compact inventory evidence, manifest
reporting and the preliminary synthetic 32K CUDA admission gate. M04 compiler implementation and all 26B runtime,
loader, allocator, arithmetic and kernel work remain out of scope.

There is no model-arithmetic or precision change in this milestone. The only GPU operation is a standalone
synthetic reservation probe; it does not upload checkpoint payload or execute the model. The expected production
memory effect remains a planning estimate until M09 repeats the gate with the compiled artifact and final arenas.

## Drift from the plan anchor

M03-relevant drift is intentional and prerequisite work:

- M00-M02 and the Windows host-test fix are integrated; M03 now follows the single-branch policy.
- `src/model/config.*`, `src/model/model_variant.*`, `include/gem16/types.h` and `src/model/manifest.cpp` contain the
  accepted explicit `gemma4_moe_26b_a4b` inspection boundary.
- M01 added immutable source locks, complete raw source inventories, source-audit tooling and numerical goldens.
- The current manifest safely parses 26B Safetensors but deliberately leaves `tensor_contract_validated=false` and
  has no 26B role/residency contract.
- The 12B runtime has mature multimodal, MTP, server and memory behavior not present at the anchor. M03 will not
  generalize or alter that execution path.

`src/model/manifest.h` and `src/model/checkpoint_loader.cpp` remain byte-identical to the anchor. No pre-existing
compiled 26B artifact, 26B CUDA execution path or final 26B memory planner exists.

## Planned implementation slice

Expected changes:

- add a model-specific 26B manifest contract with explicit `TensorRole`, `ResidencyClass`, source profile and
  producer-scale/layout metadata;
- strictly validate QAT/ordinary BF16 and external Unsloth inventories while keeping project-compiled validation a
  separate contract;
- classify all source vision bytes as compile-excluded and reject MTP/unknown extras;
- generate compact canonical role, layer, source-versus-Unsloth and compiled-byte evidence from the locked raw
  inventories;
- extend manifest JSON/summary totals by role, storage format and residency;
- add host mutation tests and a standalone CUDA reservation probe;
- update the 26B/checkpoint/memory/correctness documentation and milestone evidence.

Explicitly out of scope: quantizer implementation, payload conversion, derived checkpoint writing/loading, 26B
forward execution, MoE arithmetic, runtime memory admission, performance optimization, product exposure and M04 or
later work.

## Predeclared gates and stop conditions

Host gates cover missing/duplicate tensors, expert axis/order metadata, every router tensor, local/global V
ownership, tied-head aliasing, exact vision reconciliation, unknown/MTP rejection, external-Unsloth identity and
separate compiled validation. Real-model inspection must reconcile every Safetensors header byte. Existing 12B and
assistant tests must remain green.

The preliminary memory gate reserves the exact conservative compiled-weight estimate, 32K separate FP8 K/V,
256 MiB MoE prefill workspace, 128 MiB activation/output workspace, 32 MiB graph-private reserve and a 32 MiB
allocator/metadata guard. It passes only when direct `cudaMemGetInfo` reports at least 734,003,200 bytes free after
all regions are touched. An immutable estimate above 14,300 MiB, a source/schema mismatch, a changed 12B contract
or a failed 700 MiB direct-free gate stops M03 and leaves M04 blocked.

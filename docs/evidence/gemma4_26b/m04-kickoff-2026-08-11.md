## Bounded implementation slice

M04 will add a standard-library-only offline compiler scaffold with:

1. `plan`, `compile`, `verify` and `compare-reproducibility` CLI actions;
2. strict source-lock verification before Safetensors payload interpretation;
3. bounded-window tensor reads and a versioned encoder registry containing only `copy-v1` in M04;
4. complete source coverage: every tensor is either mapped once or explicitly excluded;
5. deterministic tensor/shard order, canonical JSON and standard Safetensors headers;
6. sibling-directory staging, fsync and atomic publication with no overwrite;
7. strict verification of source ranges, output tensors, copied metadata, provenance and every declared hash;
8. explicit restart-only interruption policy; unverified resume remains rejected;
9. process-RSS and staging telemetry under an explicit host-memory cap;
10. tiny generated multi-shard fixtures, corruption/interruption/limit mutations and retained expected hashes.

Production FP8, NVFP4 and Q4_0 encoding are explicitly out of scope. The scaffold artifact is non-production and
not runtime-loadable. It will not create a 26B artifact lock, modify the inference loader, execute repository model
code, import PyTorch/Transformers/NumPy, access a GPU or perform runtime conversion.

## Reference environment candidate

The canonical M04 byte-generation lane is Linux x86-64, little-endian, `C.UTF-8`, CPython 3.14.6, one compiler
thread and repository-controlled standard-library-only dependencies. The current filesystem reports ext2/ext3
semantics and supports same-filesystem atomic directory rename. M04 tests will freeze this policy and document that
other platforms must prove semantic identity; a release compiler run remains invalid when the repository is dirty.

## Predicted effects and pass/fail boundary

Arithmetic/precision change: none; `copy-v1` is byte identity only.

Runtime/device memory change: zero. No inference code calls the compiler.

Performance claim: none. Compiler duration is test telemetry, not model performance. The memory gate is that a
source tensor larger than the allowed staging window compiles without whole-tensor allocation, observed RSS remains
below the supplied absolute cap, and the report records both values.

M04 passes only if two independent synthetic runs are byte-identical, every output byte has source provenance,
vision exclusion reconciles exactly, malformed/corrupt/interrupted cases leave no published artifact, verification
recomputes every source/output hash, the host/sanitizer/Python and relevant 12B gates pass, and M05-M07 can register
new deterministic encoders without changing compiler orchestration.

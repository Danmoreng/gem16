## What changed and why

The installed vLLM0.33.0 source and today's prior actual12B D3 trace show
CUTLASS SM120 FP8 projections with a16×64×128 tile and
`SM120_16x8x32_TN` atoms. Query rows share the matrix tile. The native parent
instead reuses each weight fragment across four separate MMA accumulators.
`P/vllm-fp8-reference.json` records the installed source SHA256 and observed
launches; `P/vllm-fp8-kernels.txt` retains demangled actual kernel names.
No model repository code is executed and no new package is installed.

`src/cuda/fp8/sm120.cu` adds `TwelveBD3PackedFp8ProjectionKernel` and selects
it only for four-row12B QKV/O shapes (hidden3840; local Q/K/V4096/2048/2048,
global Q/K8192/512, O3840×4096/8192). Four actual rows share one M16/K32
MMA.32 ephemeral shared-memory padding bytes/row avoid bank conflicts.
Weights, K32 accumulation order, FP32 scale order and all BF16/FP8 boundaries
stay identical. There is no persistent weight copy, runtime repack, new
allocation, new precision, default-depth or model-profile change. These
same four-row shapes can also occur in a short12B batch; their outputs are
byte-exact. T3/T5 projection branches and26B shapes remain unchanged.

The offline prototype passes all130 pinned-weight operator outputs and
three paired kernel micro-samples/case. QKV is about34.6→21µs; local O
17.5→10.3µs. These are warm operator diagnostics, not end-to-end rates.
The integrated trace records exactly1536 packed QKV/O calls in16 complete
groups. Static native MMA instructions fall20→5 in the corresponding loop
body (`P/packed.sass` versus `F/kernel-0.sass`), confirming the four-to-one
MMA mapping in the actual SM120a binary. Object resources and CUPTI geometry
are retained; object shared-memory accounting can include1024 bytes beyond
CUPTI, so the raw values are not silently equated.

The diagnostic FP8-family cost falls5.46097→3.53083ms/group.
D2's prior family cost is3.52471ms/group: four rows now amortize nearly as
well as three in this family, matching the useful scaling property seen
in vLLM. Profiled timings have distinct states/instruments and coarse
fusion boundaries; they are not an exact decomposition of primary throughput.
Attention (4.980ms/group) and norm/quantization
(2.197ms/group) remain the main gaps against the prior
vLLM D3 diagnostic2.394/0.982ms. vLLM uses tiled Triton dot products;
copying that attention arithmetic would require an explicit numerical-path
qualification. This patch keeps native exact arithmetic throughout.

## D3 implementation and correctness

D3 admission covers12B CLI/chat/server/SDK, fixed depth3 and a distinct D3
group counter/metric. Adaptive D3 remains unsupported. Four row controls,
3×context proposals and four-row host-chain capacity are preallocated.
The conditional graph owns branching, positions, sampling step, acceptance,
KV commit, reasoning, stop/tail routing and256-slot mapped-ring streaming.
The actual captured range has one cudaGraphLaunch and no synchronization or
allocation APIs; no per-group host decision is introduced. Complete safe
D3 groups use four verifier rows; ordinary child execution handles short
and reasoning-sensitive tails. Group counts remain437, proposals1311,
accepted694, rejected617,440 Target batches and1751 Target row-forwards.

The four-row extensions include shared-K/V local/global attention, packed
FP8 QKV/O, fixed head, post-attention/residual/pre-MLP quantization fusion,
fixed Down and the dense Gate/Up short-batch policy. The D3 audit also
completes the previously missed local-attention normalization specialization
for T4/T5 while preserving each item's exact two-level reduction tree.

A direct ordinary oracle finds a carried first-window-crossing addressing
case: a row beyond position1023 must shift its own window and cap its token
count. The owned T4/T5 paths are corrected; T3 is left unchanged.42 synthetic
cases per row count cover short contexts, the crossing, wrapped windows and
large finite inputs. Five full-model prompt lengths1019..1023 compare all32
outputs and the whole KV cache with ordinary. Compressed ordinary references
are retained in `F/window-boundary/`; matching candidate payloads are checked
and hashed, then removed. Full16K KV copies are byte-identical immutable
hard links to the retained original, avoiding duplicate disk allocation.

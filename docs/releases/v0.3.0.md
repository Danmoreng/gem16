# gem16 0.3.0

gem16 0.3.0 collects the qualified Trellis35 decode improvements since 0.2.1
and fixes Windows release compilation. Packages target Windows x64 and Linux
x86-64 on Blackwell SM120/SM120a, with Studio plus server archives and separate
headless server archives. Model weights download separately.

## Changes

- Fixed-D2 graph capture and mapped-ring atomics are corrected. Resident
  decoding retains the existing sampling, cache and fixed-D2 semantics.
- The 26B Trellis35 path avoids redundant allowed-winner selection and retains
  the accepted Down/GateUp codec-window and warp changes, fixed-D2 attention
  normalization, three-row FP8 QKV/O packing and shared RoPE tables.
- Ordinary Trellis35 local attention stages the existing FP8 value ring for
  the qualified 1,024-slot path. Precision, model locks and context policy are
  unchanged. Rejected experimental kernels remain diagnostics.
- Quality scripts protect resumed runs against reference changes. Linux Studio
  packaging configures its build directory before building.
- The Windows selection test uses the existing portable environment lookup,
  resolving MSVC C4996 under warnings-as-errors without weakening compiler checks.
- The generated CI Python environment is excluded from Git status so release
  manifests report the source tree state without counting installed test tools.
- Current native and llama.cpp comparisons include their exact revisions,
  timing boundaries, formats, raw samples and VRAM measurements.

## Validation scope

The retained Linux SM120a campaigns include exact parent/candidate boundaries,
token parity, operator and integrated sanitizer checks, protected 12B and
internal NVFP4 regressions, and bounded Compact Vision image and lifecycle
checks. These results belong to their recorded implementation revisions;
they are not exact-0.3.0 two-platform GPU qualification.

The [five-step closeout](../evidence/gemma4_26b/decode-five-steps-final-2026-10-24.md),
[RoPE qualification](../evidence/gemma4_26b/n1-rope-qualification-2026-11-05.md)
and [local-attention qualification](../evidence/gemma4_26b/local-attention-o-2026-11-05.md)
describe the measured scope. Performance gains are workload-specific; the
separate experiments must not be added together into a release-wide speed claim.

Release candidates must pass Windows and Linux build/host/Studio checks,
native Blackwell instruction verification, archive contents/version/manifest
checks and SHA-256 verification before attachment. Hosted runners have no
NVIDIA GPU and do not qualify model execution.

Publication status and exact-candidate build evidence are recorded in the
GitHub release. The standing owner policy of 2026-11-08 authorizes stable 0.3.0
publication and removes full GPU/clean-machine/download campaigns and a full
qualification manifest from mandatory release work for this and future versions.
Release notes report actual checks and limitations without claiming omitted
campaigns passed.

## Known limitations

- The retained Linux in-flight cancellation probe reproduces a pre-existing
  streaming status inconsistency: some cancellations report an internal
  inconsistency rather than the cancellation status. Poisoned-session rejection
  and reset recovery matched the parent. This issue remains open.
- Recent optimization qualification ran on Linux. Exact-release Windows GPU,
  extended media/everyday-context and clean-machine qualification is not claimed.
  The bounded Compact Vision check covers one scene; robust 12B small-detail
  image recall remains unqualified.
- OpenAI compatibility remains the explicit Agent Core v1 subset. Reasoning
  replay, other per-request sampling overrides, required/named tool choice and
  `parallel_tool_calls=false` remain outside that subset. Native response
  penalties remain Chat Completions controls; Responses is unchanged.
- 12B Unified supports text, images and audio. 26B Compact Vision supports text
  and images, one execution slot and its optional pinned fixed-D2 Assistant.
  The text-only 26B NVFP4 profile remains internal regression/rollback.
- Packages require the declared platform libraries and NVIDIA driver/runtime;
  they are not universally self-contained. One local user on loopback remains
  the supported boundary; remote multi-user serving, authentication and TLS
  are outside this release.
